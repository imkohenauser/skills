# 無生物主語の見直し

AIは英語の組み立てのまま日本語を書くことがあり、事柄や抽象名詞を主語にした文が増える。ここでは、そうした文だけを見つけて日本語らしい形に直す。文章全体の推敲はしない。

## 直す4つの型

1. 指示語：前の節や文の内容を「それは」「これは」で受けて、判断や評価を述べる文。
2. 因果：原因になった事柄を主語にして、結果を述べる文（〜が〜を速くした、〜が〜を半分にした、〜が〜をもたらした、〜が〜につながった、〜が〜させた）。
3. 可能：事柄を主語にして、できること・できないことを述べる文（〜を可能にする、〜を許す、〜を妨げる）。
4. 判断：データや結果を主語にして「〜を示唆する」「〜を示している」と述べているが、実際には書き手が推し量っている文。

## 残す文

4つの型に当てはまっても、次の文は直さない。

- システムやコードが自分でする動作を述べる文（このAPIはJSONを返す）
- 識別子が主語の文
- 自然現象（台風が各地に被害をもたらした）
- 定着した言い方（この薬は痛みを和らげる）
- 主語にした物の働きがすぐ分かる文（センサーが異常を検知する）
- 図表の内容を述べる文（表1は月ごとの売上を示す）
- 引用やコードの中の文

## 手順

1. 候補を拾う。4つの型に挙げた形を探す。「それは」「これは」は、文の途中のものも拾う。
2. 候補の文を英語に戻してみる。主語が it、this、抽象名詞になり、述語が make、allow、enable、prevent、cause、lead to、show、suggest、look like になれば直す対象にする。当てはまっても、日本語でふつうに使う言い方なら残す。
3. 次の直し方を上から順に試し、必要なら組み合わせる。
   1. 主語を消す。
   2. 原因や根拠を「〜で」「〜て」「〜ので」「〜と」「〜た結果」「〜から」の節にする。
   3. 結果を自動詞や可能の形で述べる（〜にした → 〜になった、〜させた → 〜した、〜を可能にする → 〜できる、〜を妨げる → 〜できない）。
   4. 書き手が推し量った内容は、書き手の判断として述べる（〜を示唆する → 〜と考えられる、〜を示している → 〜と分かる）。
   5. 人を主語にする。原文か前後の文にその人が書いてあるときだけ使う。
4. 直した文を元の文と読み比べ、因果の強さ、誰の判断か、断定と推量の強さ、時制の4点が変わっていないかを確かめる。変わっていたら元に戻し、候補として返す。

決めきれない文は直さない。文を削る、2文を1文にまとめるといった変更は本文に入れず、「残した候補」に提案として書く。

## 例

直す例

- 問題が残っていると、それは確認不足に見える。→ 問題が残っていると、確認不足に見える。
- キャッシュの導入が応答時間を半分にした。→ キャッシュの導入で、応答時間が半分になった。
- この設定は複数環境の切り替えを可能にする。→ この設定を使うと、複数の環境を切り替えられる。
- 確認の省略が障害につながった。→ 確認を省いた結果、障害が起きた。
- この結果は設計の見直しの必要性を示唆している。→ この結果から、設計を見直す必要があると考えられる。
- 締め切りの接近がチームに焦りをもたらした。→ 締め切りが近づき、チームに焦りが出た。

直しすぎの例

- このツールはログを集める。→ ✗ 私たちはこのツールでログを集める。（残す型の文に、原文にない人を足している）
- この変更が障害をもたらした。→ ✗ この変更で障害が起きたかもしれない。（断定が推量に弱まっている）

## 出力

該当がなければそう返し、空の見出しは出さない。

### 直した本文
（本文全体。直さなかった文もそのまま含める）

### 変えたところ
- 元の文 → 直した文（型の番号）

### 残した候補
- 文（残した理由。書き手に確かめたいことや提案があれば添える）
